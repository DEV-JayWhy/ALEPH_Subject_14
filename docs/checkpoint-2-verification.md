# 중간 점검 2차 — 구현 및 검증 기록

작성일: 2026-10-21 (한국 시간)

## 사용자 흐름

관리자 작성/수정 화면의 공개 범위 선택 → posts INSERT/UPDATE → PostgreSQL RLS → 회원 상태에 따른 목록·본문·이미지 반환. 관리자 전체 회원의 추방 → profiles 상태 변경 → 이후 비공개 데이터 접근 및 새 앱 로그인 차단.

## 구현

- 공개/비공개 선택과 읽기 대상 안내. 관리자만 수정·삭제 버튼과 편집 경로 접근 가능.
- 수정 시 기존 HTML·이미지 로딩. 이미지 로딩 실패 시 수정 진입을 중단해 기존 이미지를 누락 저장하지 않음.
- updated_at 조건부 UPDATE로 동시에 수정된 내용 덮어쓰기 방지. 저장 실패 시 편집 내용 유지.
- 삭제 확인 → 게시물 삭제 → 첨부 파일 정리. 파일 정리 실패를 별도 안내하고, 게시물 없이는 Storage 읽기 정책이 접근을 거부함.
- 승인 회원에만 추방 버튼, 회원/admin 역할과 이전 승인 상태를 조건으로 갱신. 관리자 계정 추방 UI 없음.
- 새 앱 로그인은 거절·추방 상태 차단. 기존 JWT라도 RLS는 현재 profiles 상태를 조회함.
- 로그인 중 화면은 포커스 복귀·15초 간격 상태 확인. 읽는 글은 새 요청으로 갱신하고 기존 blob URL 해제. 이미 사용자에게 전달된 자료를 회수하는 기능은 아님.
- 정렬, 글꼴, 글자 크기, 강조색, 구분선, 서식 초기화, 표 행/열 편집·셀 병합/분할, 서식 버튼 적용 상태.

## 분리된 브라우저 UI 검증 — 운영 API와 연결하지 않은 테스트

실제 src/main.js와 Tiptap·DOMPurify를 사용하되 DB 클라이언트만 로컬 모의 저장소로 대체했다. HTTP QA 환경에 없는 crypto.randomUUID만 테스트용 ID 생성으로 대체했다. 이 대체 코드는 저장소나 배포본에 포함하지 않는다.

- 비공개 선택 후 제목·본문 저장 → 비공개 배지와 내용 표시 확인.
- 기울임·가운데 정렬·20px·형광펜 적용 → 저장 후 HTML과 새로고침 후 수정 화면에서 유지 확인.
- 제목 수정·공개 전환 → 수정 저장 후 제목 및 배지 변경 확인.
- 표 삽입 후 아래 행·오른쪽 열 추가 → 4행 4열 확인, 수정 저장 후 표 재열람 확인.
- 전체 회원에서 관리자 계정의 추방 버튼 미표시, 승인 회원의 추방 버튼 표시.
- 테스트 회원 추방 확인창 → 상태가 이용 권한 해제로 변경됨 확인.
- 이 결과는 실제 Supabase 인증/권한 통과 증거와 구분한다.

## 자동 검사

- npm test 9개 통과, npm run build 성공.
- 실제 익명 API 검증 4개 통과: 공개 글만 반환, 프로필 조회 거부, 글 생성 거부, 내부 권한 함수 RPC 노출 없음.
- 로그아웃 처리 중에는 기존 본문을 즉시 지우고 인증 종료를 기다린다. 로컬 상태가 미승인이면 목록/상세 쿼리도 공개 글로 한정하여 이전 JWT가 남은 짧은 구간의 화면 노출을 방지한다.

## 서버 검증 한계

- 기존 posts/profiles/Storage 정책 존재와 구현 조건을 확인했다. 이번 단계에서는 데이터베이스 스키마나 권한 정책을 변경하지 않았다.
- tests/phase2-rls.sql: 기존 계정만 사용하고 트랜잭션 후 ROLLBACK하는 전체 권한 검증 스크립트를 준비했다.
- SQL 실행 도구가 Invalid or expired requestState를 반환했다. 실행 성공이나 정책 전체 통과로 기록하지 않는다. 이후 read-only 조회에서 테스트용 게시물/이미지 행 0건 확인.
- 실제 승인 회원의 비공개 글·이미지 열람, 비로그인·대기·거절·추방 계정 직접 URL/API 차단은 사용자 확인 대기.
- 실제 운영 게시물 수정·삭제와 이미지 업로드/보존/삭제, 회원 추방 후 기존 세션 접근 차단, 모바일 실제 조작은 확인 대기.

## 다음 실사용 확인 순서

1. 관리자에서 테스트 글을 비공개로 저장한다. 로그인하지 않은 창에서 목록과 직접 주소 접근이 차단되는지, 승인 회원은 볼 수 있는지 확인한다.
2. 관리자에서 같은 글을 수정하고 공개로 바꾼 뒤 비로그인 열람과 이미지·서식 유지를 확인한다. 테스트 글을 삭제하고 직접 주소도 확인한다.
3. 테스트 회원을 로그인시킨 상태에서 관리자로 추방한다. 해당 회원의 비공개 글 새로고침·이미지 요청과 재로그인 차단을 확인한다.

추방 테스트에는 실제 이용을 계속할 계정 대신 사용자가 테스트용으로 정한 계정을 사용한다. 비밀번호는 공유하지 않는다.


## v7 사용자 실사용 확인 및 블랙 관리

- 사용자 확인: 기존 글 비공개 전환 후 비로그인 목록에서 미표시, 승인 회원의 비공개 열람 성공. 수정·공개 전환 후 비로그인 정상 열람. 회원 차단 후 비공개 전환된 글 미표시.
- 기존 승인 회원 manda1714는 과거 이메일 미인증 상태로 로그인이 실패했다. 기존 승인 계정의 인증 상태만 정리하고 비밀번호는 변경하지 않았으며 이후 회원 로그인·비공개 열람을 사용자가 확인했다.
- 사용자 요청으로 추방 UI를 블랙 처리로 변경하고 블랙 목록과 해제 버튼을 추가함. DB의 기존 expelled 상태를 그대로 사용하므로 기존 차단 계정도 표시된다.
- 관리자만 approved → expelled(블랙), expelled → pending(해제), pending → approved/rejected(재심사)를 수행하도록 화면 액션의 이전 상태를 조건으로 갱신한다. 블랙 해제는 자동 승인/계정 삭제/비밀번호 변경을 하지 않는다.
- 실제 블랙 해제 → 승인 대기 → 재수락 → 기존 비밀번호 로그인은 사용자 확인 대기.
- 분리된 QA 브라우저에서 블랙 목록의 기존 차단 회원 표시, 블랙 해제 확인창, 목록에서 제거, 승인 대기 목록으로 복귀 및 수락/거절 버튼 표시를 확인했다. 실제 운영 회원 상태는 이 테스트에서 변경하지 않았다. 빌드와 기존 자동 테스트 9개 통과.


## v8 동적 카테고리·대표 이미지·이전/다음 글

### 구현

- 블로그 수정 페이지 /settings는 관리자 전용. categories와 category_images는 일반 방문자 읽기, 관리자만 변경할 수 있도록 RLS 설정. 대표 이미지는 공개 블로그 설정으로 안내.
- 기존 분류 4종과 게시물 연결을 유지했다. FK ON UPDATE CASCADE, ON DELETE SET NULL로 이름 변경은 글에 반영하고 분류 삭제는 글을 미분류로 보존한다.
- 기본 SVG 이미지 12종과 사용자 이미지 다중 등록(최대 10개/각 5MB). 파일은 별도 private category-images bucket에 두고 카탈로그에 등록된 경로만 방문자가 다운로드할 수 있다. 관리자만 업로드·정리 가능.
- 이전·다음 글은 작성 시각+UUID로 안정적으로 정렬하고 현재 글과 이웃 글 모두 SECURITY INVOKER RPC 및 posts RLS를 적용한다. 익명/미승인 화면은 public_only 옵션도 사용한다.

### 확인한 결과

- 분리된 QA: 카테고리 추가와 대표 이미지 선택 후 메뉴 갱신, 기존 카테고리 이름 변경, 이미지 2개 동시 등록과 선택 목록 추가 확인.
- 분리된 QA: 공개 3개·비공개 2개를 섞은 5개 글에서 동일한 공개 글 하단이 관리자에게 이전/다음 비공개 글로, 방문자에게 그 비공개 글을 건너뛴 이전/다음 공개 글로 표시됨 확인.
- 운영 API: 익명 categories/image catalog 읽기 허용, 카테고리 생성·이미지 카탈로그 등록은 42501 RLS 거부 확인. 존재하지 않는 현재 글 및 실제 비공개 현재 글을 이용한 RPC는 빈 목록으로 반환되어 이웃 제목 비노출 확인.
- 입력 및 이미지 경로 검증 포함 자동 테스트 11개, 빌드 성공. API 통합 검사 7개 통과.
- 보안 advisor 신규 경고 없음. 기존 private 요청 제한 테이블 정책 없음 INFO와 유출 비밀번호 검사 비활성 WARN은 이전 단계와 동일하며 모든 경고가 해결됐다고 기록하지 않는다.

### 확인 범위의 한계

- 실제 운영 DB는 발행된 비공개 글 1개, 공개 글 0개인 상태에서 API 검증했다. 공개 글 사이 순서 비교는 운영에서 실행할 자료가 없어 분리된 QA 결과와 구분한다.
- 카테고리 이름 변경/삭제에 대한 ROLLBACK 서버 검증 요청은 도구의 Invalid or expired requestState로 결과를 얻지 못했다. 테스트 카테고리와 글 행이 0건임을 후속 조회로 확인했다. FK 정의와 배포는 확인했지만 실제 운영 관리자 CRUD 성공은 사용자 확인 대기다.
- 운영 관리자 이미지 업로드·새로고침 후 대표 이미지 유지, 분류 삭제 후 기존 글 미분류 유지, 실제 승인 회원·비로그인 이전/다음 글 비교는 사용자 확인 대기다.
- 모바일 점검은 사용자 요청으로 보류했다.

## v9 최종 단계 — 2026-10-26

- 사용자 확인: 카테고리 관리, 수정·삭제 성공. 이미지 등록·삭제된 분류의 글 보존은 별도 추가 확인을 완료했다고 해석하지 않음.

## v10 스크롤 초기화 오류 — 2026-10-26

- 사용자 제보: 게시글을 읽는 중 주기적으로 위로 이동함. 로그인 시 15초 타이머와 포커스 복귀에서 게시글 전체 render를 실행하던 코드 확인.
- 권한·글 상태가 같으면 본문을 교체하지 않도록 수정. 계정 역할/상태/ID 변경 또는 현재 글 조회 불가는 다시 그려 접근 제한을 적용. 허용된 글 내용 수정은 토스트로 안내하고 현재 본문은 보존.
- TOKEN_REFRESHED도 동일한 비파괴 검사 경로 사용. 이웃 링크는 데이터가 같으면 DOM 교체하지 않음. 요청 중 경로·세션·편집 상태 변경 시 오래된 응답 적용 방지.
- 자동 검사: 읽기 유지, 블랙/대기/역할 변경, 삭제/접근 불가, 수정 안내, 조회 실패의 분기 테스트 포함 16개 통과. 빌드 성공.
- 분리된 QA 브라우저에서 로그인된 관리자와 50문단의 긴 글을 사용했다. PageDown으로 내린 뒤 안정된 scrollY=819를 기준으로 38.638초 후에도 scrollY=819 유지 확인(15초 주기 두 번 이상). 운영 계정의 재확인은 사용자 확인 대기.
