- 새 아이디 방식의 정상 가입·로그인 사용자 확인

트랜잭션 기반 전체 권한 검사 tests/rls.integration.sql은 준비했으나 실행 도구가 Invalid or expired requestState 오류로 종료하여 통과로 기록하지 않음. 계정 자동 생성 요청은 실행이 거절되었고 실제 생성 계정 0건을 확인했다. 초기화용 함수는 410 응답만 반환하도록 비활성화했다.

1차 최종 제출은 관리자 초기 등록 및 실제 사용 흐름 검증 후 진행한다.

## v4 아이디 가입 전환

- 인증 메일 발송 한도(429 over_email_send_rate_limit)를 실제 Auth 로그에서 확인. 사용자 요청으로 아이디·비밀번호 가입 방식으로 전환함.
- 기존 프로필 2건에 username을 추가하고 비밀번호·Auth UUID·승인 상태·글 1건을 보존함.
- 관리자 아이디 admin, 기존 승인 회원 아이디 manda1714.
- 가입·로그인은 account-access 서버 함수가 수행하며, 가입은 pending/member를 고정하고 권한은 기존 RLS로 검사함. 비밀번호는 Supabase Auth에서 해시·검증함.
- 입력 검증·빌드 검사 완료. 신규 계정을 임의로 만들지 않았으며 정상 가입과 기존 비밀번호 로그인은 사용자 확인을 기다림.
- 내부 요청 제한 테이블은 비공개이며 일반 사용자에게 권한·정책을 부여하지 않음. 보안 점검의 RLS 정책 없음 INFO는 이 테이블의 의도한 기본 거부 상태임. 유출 비밀번호 검사 WARN은 기존 Free 플랜의 비활성 기능이며 이번 전환에서 변경하지 않음.


## v5 거절 후 재신청 보완

- 사용자 확인: 아이디 방식에서 가입 거절 후 승인 대기 목록에서 사라짐, 해당 계정 로그인 불가. 이어 같은 아이디로 재신청 시 중복 오류 제보.
- 서버에서 기존 비밀번호를 검증한 거절 회원만 같은 UUID로 승인 대기로 되돌림. 임시 검증 세션은 반환하지 않고 종료하며 비밀번호와 권한은 변경하지 않음.
- 승인·대기·추방·관리자 계정 변경 차단, 잘못된 비밀번호/다른 UUID 차단, 관리자 동시 처리 시 조건부 갱신, 세션 종료 실패 처리를 자동 테스트함.
- 실제 거절 계정의 올바른 비밀번호 재신청→관리자 재승인 흐름은 사용자 확인 대기. 사용자의 비밀번호를 임의로 설정하거나 테스트 계정을 생성하지 않음.
