# 학습 기록 블로그 — 계획 설계서

- 버전: v9
- 작성일: 2026-10-26
- 상태: 최종 단계 · 카테고리 실사용 확인 및 이전/다음 글 배치 조정

## 1. 프로젝트 목표

수업 내용과 개인 공부 내용을 글·이미지·표·코드로 기록하고, 공개 범위에 따라 방문자 또는 승인된 회원에게 공유하는 블로그를 만든다.

운영자 본인의 학습 기록을 중심으로 한다. 누구나 공개 글을 읽을 수 있고, 가입 신청 후 관리자에게 승인받은 회원은 로그인하여 비공개 글도 읽을 수 있다.

## 2. 핵심 기능 3가지

### ① 관리자 전용 게시물 작성·수정·삭제

- 관리자 계정을 서비스 운영 전에 미리 준비한다.
- 글 작성·수정·삭제 버튼은 관리자에게만 표시한다.
- 제목과 본문을 입력하고 이미지와 서식을 활용하여 글을 작성한다.
- 수정한 내용은 다시 열거나 새로고침해도 유지된다.
- 삭제 전 확인을 받고 삭제 결과를 안내한다.
- 버튼 표시와 별도로 서버 또는 데이터 접근 정책에서도 관리자 권한을 검증한다.

### ② 게시물 공개·비공개 설정

- 작성 및 수정 시 공개 여부를 선택한다.
- 공개 글은 비로그인 방문자도 목록과 본문을 볼 수 있다.
- 비공개 글은 승인된 회원 및 관리자가 로그인한 경우에만 볼 수 있다.
- 비공개 글의 제목·요약·본문·첨부 이미지 등이 비로그인 응답에 포함되지 않도록 한다.
- 글 주소나 이미지 주소를 직접 입력해도 동일한 권한 정책을 적용한다.
- 공개에서 비공개로 변경하면 이후 접근에서도 변경된 권한을 적용한다.

### ③ 가입 승인 및 회원 관리

- 방문자는 가입을 신청하고 승인 대기 상태가 된다.
- 관리자는 관리자 전용 탭에서 가입 신청을 수락하거나 거절한다.
- 거절된 아이디는 가입 화면에서 기존 비밀번호로 본인 확인 후 재신청할 수 있다. 기존 계정·비밀번호를 유지하고 승인 대기로 돌아가며 관리자 승인을 다시 받아야 한다.
- 비밀번호가 다르거나 승인·대기·추방된 계정이면 재신청으로 상태를 바꿀 수 없다. 거절·추방 상태에서는 앱 로그인을 차단한다.
- 승인 전 또는 거절된 계정에는 비공개 글 열람 권한을 부여하지 않는다.
- 관리자는 승인된 회원을 블랙 처리하고, 블랙 목록에서 해제할 수 있다.
- 블랙 상태에서는 새 앱 로그인과 같은 아이디 재가입 신청을 차단하며 기존 세션도 비공개 자료에 접근하지 못한다.
- 블랙 해제 시 기존 계정·비밀번호를 유지하고 승인 대기로 이동한다. 관리자 수락 후 비공개 자료를 다시 열람할 수 있다. 기존 추방 상태의 계정도 블랙 목록에 표시한다.
- 추방된 회원은 기존 로그인 상태라도 이후 요청에서 비공개 글에 접근할 수 없다.
- 일반 회원에게 관리자 탭을 표시하지 않으며 관리자 주소나 API 직접 접근도 차단한다.
- 일반 회원은 공개·비공개 글을 읽을 수 있지만 글을 작성·수정·삭제할 수 없다.

## 3. 권한 설계

| 사용자 상태 | 공개 글 열람 | 비공개 글 열람 | 글 작성·수정·삭제 | 회원 관리 |
| --- | --- | --- | --- | --- |
| 비로그인 방문자 | 가능 | 불가 | 불가 | 불가 |
| 가입 승인 대기·거절 계정 | 가능 | 불가 | 불가 | 불가 |
| 승인된 일반 회원 | 가능 | 로그인 시 가능 | 불가 | 불가 |
| 추방된 회원 | 가능 | 불가 | 불가 | 불가 |
| 관리자 | 가능 | 로그인 시 가능 | 로그인 시 가능 | 로그인 시 가능 |

가입·로그인은 이메일 인증 없이 아이디와 비밀번호를 사용한다. 관리자의 가입 수락 여부로 비공개 자료 접근을 제한한다.

관리자 권한과 가입 승인 상태는 사용자가 임의로 바꿀 수 없도록 한다. 관리자 계정의 비밀번호나 비밀 키를 소스 코드·계획서·제출 자료에 기록하지 않는다. 승인 전 로그인을 허용할지는 구현 시 결정하되 비공개 글 열람은 승인 이후에만 허용한다.

## 4. 글쓰기 편집기 범위

다양한 꾸미기 기능을 제공하는 리치 텍스트 편집기를 사용한다. 아래는 구현 목표이며, 실제 지원 여부와 동작을 검증하여 완료 여부를 기록한다.

### 기본 서식

- 제목 단계, 글꼴, 글자 크기, 글자색, 배경색
- 굵게, 기울임, 밑줄, 취소선
- 문단 정렬, 들여쓰기, 줄 간격
- 번호 목록, 글머리 목록, 체크 목록
- 인용문, 구분선, 링크 삽입·수정·해제
- 실행 취소·다시 실행, 서식 지우기

### 이미지·표·학습 기록

- 이미지 파일 업로드, 붙여넣기, 끌어놓기
- 이미지 크기·정렬 조절, 설명과 대체 텍스트
- 표 삽입, 행·열 추가 및 삭제, 셀 병합과 분할
- 인라인 코드 및 코드 블록, 언어 선택과 구문 강조
- 코드 복사, 특수문자와 이모지
- 동영상·외부 콘텐츠 삽입은 지원 형식과 공개 범위 보호 가능 여부를 확인하여 적용

### 작성 편의

- 저장 전 미리보기, 전체 화면 편집, 글자 수 표시
- 임시 저장 및 작성 중 이탈 안내
- 저장 진행·성공·실패 표시와 실패 시 내용 보존
- 편집기에서 설정한 서식이 실제 게시물 화면에도 유지되도록 확인

필수 완성 기준은 글·이미지·기본 서식·표·코드 블록의 작성과 저장, 재열람이다. 나머지 편집 기능도 폭넓게 구현하되 지원하지 않거나 동작이 확인되지 않은 기능을 완료했다고 표시하지 않는다. 유료 기능이나 외부 서비스가 필요한 항목은 적용 전에 비용 및 대안을 확인한다.

## 5. 화면 구성

### 블로그 수정 및 글 탐색

- v9 사용자 확인: 카테고리 관리 및 수정·삭제 동작을 확인했다. 이미지 등록은 별도 확인 대기로 유지한다.
- 사용자 요청으로 글 하단은 다음 글을 왼쪽(← 다음 글), 이전 글을 오른쪽(이전 글 →)에 배치한다. 좁은 화면에서는 다음 글이 위, 이전 글이 아래에 표시된다. 글을 찾는 순서·공개 범위 정책은 유지한다.

- 관리자 공간에 블로그 수정 탭을 추가하고 상단 카테고리 관리에서 추가·이름 변경·삭제·대표 이미지 선택을 제공한다. 추후 테마 등 설정을 확장할 수 있는 화면으로 구성하며 테마 기능은 이번 범위에 넣지 않는다.
- 고정 카테고리 목록을 DB 관리 방식으로 바꾸고 기존 카테고리·게시물 연결을 보존한다. 이름 변경은 기존 글에도 반영하고, 삭제는 글을 삭제하지 않고 미분류로 이동시킨다.
- 기본 카테고리 이미지 12종(노트·네트워크·보안·개발·터미널·클라우드·책·실험·데이터베이스·폴더·아이디어·지구)을 제공한다. PNG/JPG/WebP/GIF를 한 번에 최대 10개, 파일당 최대 5MB로 등록하고 카테고리마다 선택한다.
- 카테고리 이름과 이미지는 모든 방문자에게 표시하는 공개 블로그 설정이다. 이미지 저장소는 비공개 bucket으로 두고 등록된 카테고리 이미지만 공개 읽기를 허용한다. 등록·수정·삭제는 서버 RLS에서도 관리자만 허용한다.
- 게시물 하단의 이전 글은 더 오래된 글, 다음 글은 더 최신 글이다. 같은 작성 시각이면 UUID 순서로 정렬하여 누락·중복 없이 찾는다. 전체 게시물 중 현재 계정이 읽을 수 있는 발행 글만 연결한다.
- 비로그인·미승인 계정에게 비공개 이전/다음 글의 제목·주소를 반환하지 않는다. 조회 함수는 SECURITY INVOKER로 현재 글과 이웃 글 모두 기존 RLS를 적용한다.
- 현재 운영 글은 비공개 1개이므로 여러 글의 순서 조합은 분리된 QA에서 검증하고, 실제 운영 계정별 이전/다음 글 확인은 추가 글 작성 후 진행한다.


1. 블로그 홈: 접근 가능한 게시물 목록, 제목, 작성일, 요약 표시
2. 게시물 상세: 본문, 이미지, 표, 코드 표시 / 관리자에게 수정·삭제 버튼 표시
3. 로그인 및 가입 신청: 로그인, 신청, 승인 대기·거절 상태 안내
4. 관리자 글쓰기: 제목, 편집기, 공개 여부, 미리보기, 저장
5. 관리자 페이지: 가입 신청 목록, 수락·거절, 승인 회원 목록, 추방

PC와 모바일에서 읽기 편하도록 구성한다. 게시물이 없는 상태와 조회 실패 상태를 구분하고, 실패 시 다시 시도할 방법을 제공한다.

## 6. 구현 및 제출 순서

### 현재 구현 구성 및 진행 상태

- v7: 회원 관리에서 블랙 처리·블랙 목록·블랙 해제를 제공한다. 블랙 해제는 expelled → pending이며 자동 승인하지 않는다. 비공개 열람·공개 전환·차단 후 비공개 미표시는 사용자 확인, 해제·재수락 흐름은 확인 대기다.

- 화면: Vite 기반 웹앱. PC·모바일 블로그 목록·상세, 검색·주제 필터, 로그인·가입 신청, 관리자 회원 관리, 관리자 글쓰기.
- 인증 및 저장: 전용 Supabase 프로젝트 ALEPH_Subject_14(서울 리전), Supabase Auth, PostgreSQL RLS, 비공개 이미지 저장소.
- 편집기: Tiptap. 기본 서식, 제목, 목록, 인용, 링크, 코드 블록, 표, 글자색, 이미지 업로드·붙여넣기·끌어놓기를 우선 구현한다.
- 1차는 공개 글 작성, 가입 수락·거절·재신청·로그인을 사용자 확인했다. 2차에 공개 범위 선택, 글 수정·삭제, 승인 회원 추방 UI와 추가 편집 도구를 구현한다.
- 2차 편집 도구에 문단 정렬, 글꼴·글자 크기, 형광펜·강조색, 구분선, 서식 초기화, 표 행·열 추가·삭제와 셀 병합·분할을 추가했다. 버튼의 적용 상태를 표시한다.
- 글 수정 시 기존 이미지·서식을 불러오고 공개 범위를 바꿀 수 있다. 다른 창에서 이미 수정·삭제된 글은 이전 내용으로 덮어쓰지 않는다.
- 삭제는 확인을 받은 후 수행한다. 게시물 삭제로 첨부 이미지 접근을 차단한 후 파일 정리를 시도하며, 파일 정리 실패는 따로 안내한다.
- 추방된 계정의 새 앱 로그인은 차단하고, 기존 세션의 새 데이터 요청은 현재 DB 상태에 따라 비공개 글·이미지를 거부한다. 로그인 중인 화면은 포커스 복귀와 15초 간격의 상태 확인을 통해 갱신한다. 이미 열람·다운로드한 자료의 회수는 보장하지 않는다.
- 분리된 QA 화면에서 저장·재열람·수정·공개 전환·주요 서식 유지·표 행/열 추가·추방 상태 변경을 확인했다. 실제 배포 계정의 비공개 접근·수정·삭제·추방 흐름은 사용자 실사용 검증으로 이어간다.
- tests/phase2-rls.sql은 기존 계정만 사용하는 ROLLBACK 검증 스크립트다. 실행 도구가 Invalid or expired requestState 오류를 반환하여 실제 통과로 기록하지 않으며, 임시 게시물·이미지 행 0건을 확인했다.
- 가입 및 비밀번호 재설정은 최소 10자 이상을 사용하며, 11자리 비밀번호도 허용한다.
- 승인 대기 계정은 로그인해도 공개 글만 열람한다. 거절·추방 계정은 새 앱 로그인을 차단하고, 남아 있는 세션으로도 비공개 글·이미지를 조회할 수 없도록 한다.
- 관리자 비밀번호는 본인이 직접 설정한다. 초기 등록과 관리자 지정은 일반 회원 모집 전에 완료한다. 계정 준비와 화면 실사용 검증이 끝나기 전에는 1차 완료로 표시하지 않는다.
- 인증 메일 발송 한도로 가입 검증이 막혀, 사용자 판단에 따라 이메일 없는 아이디·비밀번호 가입으로 전환한다. 가입 정보는 아이디·비밀번호·이름(닉네임)이다.
- 아이디는 영문자로 시작하는 영문·숫자·점·밑줄·하이픈 3~32자이며 대소문자를 구분하지 않는다. 비밀번호는 최소 10자, 최대 128자이다.
- 기존 관리자 아이디는 admin, 기존 승인 회원 아이디는 manda1714로 연결한다. 기존 비밀번호·계정 UUID·승인 상태·게시물을 보존한다.

## 8. 질문 설계 및 작업 기록

막혔을 때는 증상, 기대한 동작, 실제 동작, 오류 문구, 시도한 방법을 기록한다. 질문에는 비밀번호와 비밀 키를 포함하지 않는다.

확인할 질문 예시:

- 비공개 글이 보인다면 화면 표시 문제인가, 서버가 권한 없이 데이터를 반환하는 문제인가?
- 회원 추방 후에도 비공개 글이 보인다면 기존 화면이 남은 것인가, 새 요청도 허용되는 것인가?
- 편집기 서식이 사라진다면 입력·저장·출력 중 어느 단계에서 달라지는가?

AI는 설계 초안, 구현, 오류 분석, 검증 방법과 문서 정리를 돕는다. 본인은 공개 범위, 가입 승인·거절 및 추방 정책, 디자인과 사용성, 최종 완료 여부를 판단한다. 제출 시에는 실제 수행한 일에 맞추어 기록한다.
